# Comments Apply and Verify Runbook

## 1. Purpose

This runbook captures the v0.7 Comments module apply and verify workflow.

The Comments module now supports the full controlled workflow:

    Export -> Generate Proposed Comments -> Dry Run -> Summary -> HTML Review -> Apply -> Verify

The apply step writes to the standard Calibre Comments field.

## 2. Safety Model

The apply script requires:

- an input TSV
- a matching dry-run CSV
- zero blocked dry-run rows
- at least one apply-eligible row
- matching current title
- matching current authors
- matching current comments hash
- supported CommentsMode
- populated ProposedComments
- exact confirmation phrase before writing

The apply script writes an apply report.

The verify script reads the apply report and confirms that current Calibre comments match the expected stored comments hash.

## 3. Managed Comments Strategy

Generated comments use a durable marker:

    <p><b>Generated By:</b> Calibre Metadata Toolkit Comments Module v0.7</p>

When existing comments are present, generated comments are prepended above:

    <hr/><h3>Original Comments</h3>

This allows the tool to preserve original publisher-style comments while making future regenerated comments replace the generated portion instead of duplicating it.

## 4. Existing Comments States

The apply script distinguishes several existing comments states:

- Blank
- UnmanagedExistingComments
- LegacyPrependHeader
- ManagedGeneratedOnly

For books with normal existing comments, the generated comments are prepended and the original comments are preserved.

For books that already contain a prior generated comments section above the Original Comments divider, the generated section is replaced instead of duplicated.

For books that contain only generated comments, the generated comments can be replaced using the durable Generated By marker.

## 5. First Real Apply Test

Test record:

    5177 - Contraband: Louis Mandrin and the Making of a Global Underground - Michael Kwass

Mode:

    CommentsMode = Prepend

Apply result:

    Rows attempted: 1
    Rows succeeded: 1
    Rows failed: 0

Verify result:

    Rows reviewed: 1
    Rows verified: 1
    Rows mismatched: 0
    Rows missing: 0
    Rows skipped: 0

Visual inspection confirmed:

- generated curator comments appear first
- durable Generated By marker appears after the generated section
- Original Comments heading appears after the generated marker
- original publisher-style comments are preserved underneath

## 6. Lessons Learned

Calibre may normalize HTML when comments are written through calibredb set_metadata.

The apply script therefore re-reads the record immediately after writing and records the hash of the Calibre-stored HTML.

The verify script checks against the stored post-apply hash, not a theoretical pre-write hash.

Invisible HTML comment markers are not durable in Calibre Comments. A visible but compact Generated By marker is used instead.

## 7. Operating Reminder

Do not apply a comments batch unless:

- dry run is clean
- summary is reviewed
- HTML review is inspected
- apply preflight is clean
- backup/export exists when testing new behavior
- verify is run immediately after apply
