# v1.6 Charter — Release-week follow-ups & console polish

## Theme

Small post-v1.5 polish across the existing layout: ship the merged PR #30
utf-8 fix with a proper version tag, close the v1.1 flag-standardisation
gap the post-v1.5 triage surfaced, kill the false-positive "hang" caused by
transient progress bars + `Prompt.ask`, and a handful of small CLI/TUI
ergonomic wins. Eight of the nine items are S-sized; one is M
(`tui/app.py` cross-step summary line). The cycle is wide rather than deep.

This is explicitly *not* the refactor cycle. v1.9 will consolidate many of
these touch points — v1.9 item 1 migrates inline `@app.command()` handlers
out of `cli.py` into `commands/<step>.py`, and v1.9 item 5 extracts a
shared review-prompt helper for the duplicated `Prompt.ask` blocks across
the five AI-suggest modules. **v1.6 polishes the existing layout; v1.9
changes the shape.** The v1.6 edits are deliberately sized to be cheap to
migrate forward once those refactors land.

## Items in shipping order

PRs land one at a time. Local Claude pauses after each merge for review and
explicit go-ahead before starting the next item.

### 1. v1.6 item 3 — `--dry-run` wiring + flag-standardisation sweep

Branch: `feat/v1.6-flag-sweep`

Audit every `@app.command()` in `cli.py:169-1222` against the canonical

Risk: low. Purely text and option-surface additions; no behaviour change
on the happy path.

### 2. v1.6 items 2 + 6 — Prompt polish (combined PR)

Branch: `feat/v1.6-prompt-polish`

**Combined call.** Items 2 (prompt discoverability) and 6 (single-letter
shortcuts) both touch the same `Prompt.ask` blocks across the five
AI-suggest modules (`authors.py`, `comments.py`, `lcc.py`,
`identifiers.py`, `tags.py`). Combining them is one coherent edit per
site — modify the choice list, add the hint line, keep word-form
compatibility — rather than two sequential passes through the same lines.
Ship as a single PR to avoid touching the same code twice and to keep
the review-prompt UX changing in one visible step.

- **Item 2.** Print `console.print("\n[dim]Waiting for input…[/dim]")`
  immediately before each `Prompt.ask("Apply changes?", ...)`, or set the
  AI-suggest progress bar to `transient=False`. Removes the
  "screen-goes-blank-then-hangs" failure mode documented in
  `docs/planning/post-v1.5-triage.md`.
- **Item 6.** Accept `a`/`h`/`r`/`s` (and `y`/`n`/`e` where applicable)
  alongside the word forms; show the letters inline in the prompt label.
  Uses Rich's `Prompt.ask` choice list directly — no wrapper.

Sites: `authors.py:116/180`, `comments.py:270/346,359,372,452`,
`lcc.py:756/843,854,865`, `identifiers.py:291/527,547`,
`tags.py:458/260,273,286,379,557`, plus `tags_review.py:137,154` and
`clean_identifiers.py:353,398` for item 6.

Alternative considered: ship items 2, 6, 8 as three sequential PRs.
Rejected — items 2 and 6 would touch the same five module files twice,
and the second pass would be obvious churn at review time.

Risk: low. UX-only.

### 3. v1.6 item 8 — Bulk-apply confirmation above threshold

Branch: `feat/v1.6-bulk-apply-confirm`

threshold (default ~20), interpose a one-line

`config.example.json`.

Ships after items 2+6 so the new confirmation prompt adopts the same hint
+ single-letter pattern established there.

Risk: low. Additive gate; no change when batch is below threshold.

## Sequencing notes

**Items 2, 6, 8 share the AI-suggest `Prompt.ask` block surface.** Items 2
and 6 are combined into a single PR (PR 2 above). Item 8 ships after, so
the new bulk-apply confirmation can adopt the hint + letter-shortcut
pattern established by 2+6. Alternative considered: three sequential PRs.
Rejected — would touch the same five module files twice and the second
pass would be obvious churn.

**Items 4 and 7 are the two TUI items.** They're independent of each
other and could ship in either order; the charter ships the smaller one
first (item 7 — digit jump, PR 5 above) and the larger one second
(item 4 — cross-step summary line, PR 6 above). Item 5 (panel coverage
for tags-review / clean-identifiers) is a CLI/module item, not TUI.

**v1.9 will consolidate these touch points.** v1.9 item 1 (migrate
top-level CLI handlers from `cli.py` into `commands/<step>.py`) and
v1.9 item 5 (extract a shared `review.py` helper for the duplicated
`Prompt.ask` blocks) together flatten the 5-module duplication. v1.6
deliberately polishes the existing layout *without* extracting the
helper — that's v1.9's job. **v1.6 is "small polish to the existing
layout," v1.9 is the refactor.** If v1.6 extracted the helper now, it
would either pre-empt the v1.9 design or have to be revisited; better to
let v1.9 build the helper informed by the polish v1.6 leaves behind.
