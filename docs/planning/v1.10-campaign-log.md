`config.json` already pins, so no config change. Decided by James from

  do-over.

4.6 comparison on real books (dry-run, ~$1); James picks the

Chosen-model smoke (2026-06-10): `clean-titles --limit 5 --dry-run` on

refreshed price table.

## The comments-wave boundary gate (added 2026-06-11)

The comments step does NOT start when the prior wave ends. When the
campaign reaches the comments boundary (earlier waves swept or James
calls it), **local Claude stops and tells James:** *"Comments boundary
reached — go finalize the revised comments format before anything
comments-related runs."* Two gates, strictly in this order:

1. **Format redesign (James, external).** James intends to rework the
   format and expectations of the comments section (a design session
   outside this repo, likely a Claude/Fable conversation). The outcome
   lands as a rules-content PR (`rules/comments.md` + its output-format
   prompt files) with the standard prompt-content real-library smoke.
   Prompt-touching → review tier before merge, per the merge-autonomy
   policy.
2. **Model A/B (the carve-out above), against the NEW format.** The
   Opus-vs-Sonnet comparison runs only after gate 1 merges — comparing
   models on a prompt that is about to be replaced answers nothing.
   James may add a Haiku arm to the same ~$1 comparison if cost is
   still a live question.

Only then does the first comments wave run. Timing note, recorded
because it's the cheap path: only ~24 books are comments-complete
today, so the format change predates scale. Comments writes ARE
audited, so those ~24 can be re-run against the new format afterwards
with `regrade --step comments-enrich --before <format-PR-merge-date>`
— a minutes-sized cleanup, not a sweep.

## Standing campaign decisions (James, 2026-06-12, library-wide)

Endorsed during clean-titles wave 1; apply across the campaign:

1. **Diacritic / special-character flattening** in both authors and titles.
   Rationale: ASCII is reliably searchable and sortable in Calibre.
2. **Award markers stripped from titles** (e.g. "(Pulitzer Prize
   Winner/Finalist)"). Award status lives in tags/metadata, not in the
   title string.

Both guide clean-titles review now; candidates for rules-content reflection
at the next rules pass.
