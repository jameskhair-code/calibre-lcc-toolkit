# v1.10 Charter — Preflight + the first full-library campaign

## Theme

Nine cycles built and cleaned the toolkit; v1.10 points it at the library.
The cycle has two phases: a four-item **preflight** that ships as the
v1.10.0 release, then the **campaign** — the first systematic enrichment of
the real ~5,000-book library, run in per-step waves. The campaign is not a
backdrop for feature work; it *is* the cycle. The old plan's cost/perf/scale
items were demoted to a triggered pull-list (`docs/planning/roadmap.md`),
built only when the run demonstrates the need.

The risk shape: preflight items are small and conventional (one rules PR,
three S–M code PRs); the campaign's risks are operational — cost, rate
limits, review stamina, and trust in what gets written at scale. The
preflight exists to take the known instances of those risks off the table
before the first wave.

## Phase 2 — The campaign

Per-step sweeps in pipeline order: **clean-titles → enrich-identifiers →
lcc-enrich → comments-enrich → tags-enrich**, then a library-wide
**tags-cleanup** pass (and tags-review where flagged). Each step sweeps the
whole library before the next begins — cross-step context (v1.4) means later
steps read earlier steps' output, so order is quality-relevant.

Wave mechanics:
- **Batch size to review stamina,** not to throughput — suggested 250–500
  books per run, adjusted freely after the first wave. `doctor && <step>`
  gating per the established habit.
- **Calibration ritual:** `audit-confidence` after the first wave of each
  step and periodically after (its first-run friction was fixed in v1.8 for
  exactly this); `audit-trajectory` at step boundaries. A tier drifting
  below threshold pauses the step for a rule edit + `regrade` pass before
  continuing — this is the v1.8 action loop running for real.
- **Capture everything:** rough edges, surprises, and pull-list trigger
  observations go to `docs/planning/inbox.md` at the moment of friction.
  Mid-campaign standalone fixes follow the PR #30/#66 precedent (small,
  measured, shipped without waiting for the boundary).
- **Pull-list discipline:** at each wave boundary, check whether any
  trigger in `docs/planning/roadmap.md` fired. A pulled item gets a normal
  PR with its premise re-verified; anything L-sized waits for v1.11 unless
  it blocks the campaign.
- **Budget:** the item-4 guardrail fronts every run; the item-2 cost table
  sets the expected total. Track actuals vs. projection in the campaign log
  (below) — the variance is itself a finding.
- **Campaign log:** a running `docs/planning/v1.10-campaign-log.md` —
  per-wave date, step, batch size, applied/declined/skipped, cost actual vs.
  projected, calibration notes. Cheap to keep, and it is the v1.11
  re-audit's primary input.

The campaign ends when James says it ends — full A-Z sweep or an explicit
stopping decision; either way the end-state (TUI pipeline line /
`count_books_with_all_columns_true`, calibration trajectories, the campaign
log) is recorded for the boundary.

## Out of scope for v1.10

- Everything on the pull-list until its trigger fires.
- New AI behaviour beyond the rules-content fixes (no new prompts, no
  subject coherence).
- TUI/display features (the polish cluster stays in LATER).
- The measurement-layer items (session report, health index, …) — the
  campaign generates their appetite signal; v1.11+ decides.

## Definition of done

- Four preflight PRs merged; `python -m pytest -q` green on `main`; the
  rules PR carried a real-library smoke.
- Campaign model decided and recorded (item 2).
- v1.10.0 released (bump, CHANGELOG, tag, GitHub Release — tag/Release
  local per CLAUDE.md) before the first wave.
- Usage tier confirmed.
- The campaign run per the mechanics above, with the campaign log kept
  current, calibration sessions at the prescribed points, and findings
  captured to the inbox.
- A closing state record (completion counts, trajectories, cost actuals)
  ready as input to the v1.11 re-audit.
